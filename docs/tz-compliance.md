## 4. Нефункциональные требования

| Требование | Статус | Как обеспечено |
|---|---|---|
| Отклик < 2 с, списки до 10 000 записей | ✅ | Серверная пагинация, индексы БД. Нагрузочный тест: 50 пользователей, 1560 компаний — 95% запросов быстрее 0,42 с, максимум 1,2 с (docs/load-test.md) |
| 50 одновременных пользователей, масштабирование | ✅ | Stateless API: несколько реплик за балансировщиком; воркеры Celery масштабируются отдельно |
| SLA 99,5%, резервное копирование ежедневно, хранение 30 дней | ✅ / 📋 | Сервис `backup` в compose; SLA обеспечивается инфраструктурой заказчика |
| RTO < 1 часа | ✅ | `scripts/restore.sh`; восстановление демо-БД занимает секунды |
| Логин/пароль, 2FA (опционально) | ✅ | TOTP (Яндекс Ключ, Google Authenticator), блокировка после 5 неудачных попыток |
| Разграничение прав: менеджер видит только свои сделки | ✅ | Проверяется на уровне API, покрыто автотестами |
| HTTPS (TLS 1.2+) | 📋 | Терминация TLS на обратном прокси — см. deployment.md |
| Шифрование чувствительных данных в БД (телефоны, пароли) | ✅ | Телефоны — AES (Fernet) + слепой индекс для поиска; пароли — bcrypt |
| Защита от SQL-инъекций, XSS, rate limiting | ✅ | ORM с параметрами, экранирование в React, 100 запр./мин на пользователя |
| Модульный монолит или микросервисы с обоснованием | ✅ | Модульный монолит — обоснование в architecture.md |
| До 500 пользователей за 2–3 года без переработки | ✅ | См. architecture.md, раздел «Масштабирование» |
