# Нагрузочное тестирование (ТЗ п. 4.1, 8.2)

**Критерий ТЗ:** 50 пользователей, списки от 1000 записей, время отклика < 2 секунд.

## Условия

| Параметр | Значение |
|---|---|
| Инструмент | Locust 2.32, сценарий `backend/tests/load/locustfile.py` |
| Пользователи | 50 одновременных, набор 5 польз./с, длительность 3 минуты, пауза 1–4 с между действиями |
| Данные | 1560 компаний, 1700+ контактов, 150 сделок, 190+ лидов, 12 месяцев истории |
| Сценарий | вход, дашборд, список компаний (100 записей на страницу, сортировка по сумме покупок), карточка компании и лента, глобальный поиск, лиды, канбан, задачи, отчёт по менеджерам |
| Путь запроса | Locust → nginx → FastAPI (4 воркера uvicorn) → PostgreSQL 16 |
| Стенд | Ноутбук разработчика, Docker Desktop (Windows, WSL2); Locust на той же машине |

## Результат

3668 запросов, **0 ошибок**, 20,5 запросов в секунду.

| Операция | Медиана, мс | 95-й перцентиль, мс | Максимум, мс |
|---|---:|---:|---:|
| Список компаний (100 из 1560) | 140 | 330 | 620 |
| Карточка компании | 75 | 190 | 510 |
| Лента событий | 66 | 200 | 340 |
| Дашборд | 230 | 530 | 890 |
| Канбан-доска | 99 | 240 | 530 |
| Глобальный поиск | 190 | 530 | 810 |
| Список лидов | 93 | 220 | 580 |
| Задачи | 66 | 190 | 500 |
| Отчёт «Эффективность менеджеров» | 84 | 250 | 370 |
| Вход (bcrypt) | 760 | 1000 | 1200 |
| **Все запросы** | **120** | **420** | **1200** |

**Критерий выполнен:** максимальное время ответа 1,2 с (вход в систему), 95% запросов быстрее 0,42 с.

## Что было оптимизировано по итогам первого прогона

Первый прогон на тех же данных выявил узкие места: канбан-доска — 95-й перцентиль 13 с, дашборд — 4,7 с,
по всем запросам — 5,9 с. Причины и исправления:

- **Каскад JOIN'ов.** Справочники компании (ответственный, отрасль, регион и др.) загружались через JOIN,
  и при выборке сделок цепочка «сделка → компания → справочники → контакт → компания → …» давала запрос
  на ~20 таблиц. Справочники переведены на пакетную загрузку (selectin), а для списков вложенные связи
  не загружаются совсем.
- **Канбан.** Доска делала по 3 запроса на каждый этап (24 запроса). Теперь один агрегирующий запрос для
  итогов и один запрос для карточек.
- **Пул соединений.** 4 воркера × 30 соединений превышали лимит PostgreSQL (100). Пул уменьшен до 15 соединений
  на воркер.

## Повтор теста

```bash
# на время теста поднимите лимиты: RATE_LIMIT_PER_MINUTE=100000, LOGIN_RATE_LIMIT_PER_MINUTE=10000 в .env
docker compose up -d backend
docker compose run --rm backend sh -c "pip install --user -q locust && python -m locust \
  -f tests/load/locustfile.py --host http://frontend --users 50 --spawn-rate 5 --run-time 3m --headless --only-summary"
```

Сырые данные прогона — `docs/load-test_stats.csv`. На сервере заказчика (выделенные ядра, Locust на отдельной
машине) показатели будут лучше, чем на ноутбуке с Docker Desktop.
